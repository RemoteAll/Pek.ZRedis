- **2026-11-18（第十二轮）· TLS 正向往返修复并纳入回归（已通过）**
  - 用户原话：**「请继续，要做完全对齐迁移」**。
  - 取证：写带阶段日志的诊断 TLS 服务端（`accepted / handshake_ok / recv hex / recv_eof`），
    实测 **TLS 1.3 握手成功但服务端零应用字节**；随后客户端打印 `readVec n=0 tls_buffered=0`。
  - **根因一（写）**：`tls_client.Client.writer.flush()` 只把密文写进 `output`（socket 写缓冲），
    不冲刷 socket（zzig `tls_client.zig` L1034-1075：`flush`/`end` 均如此，只有 `init` 末尾 `output.flush()`）。
    修复：`client.writeAll` 在 `writer.flush()` 后补 `stream_writer.interface.flush()`；
    `TlsState.destroy` 在 `end()` 后同样补冲刷（否则对端只看到 TCP FIN → 判截断）。
  - **根因二（读）**：`std.Io.Reader` 允许实现「忽略 `data`、写自身缓冲并 `return 0`」，
    zzig TLS 客户端正是该形态（应用数据 `r.end += cleartext.len` 后 `return 0`；`NewSessionTicket` 也 `return 0`）。
    旧代码把「返回 0」当 EOF → 握手成功后第一次读即误判 `ConnectionClosed`（实测服务端已回 `+PONG`）。
    修复：`resp.Reader.readSome` 的 TLS 分支改用 `peekGreedy(1)` + `toss(n)`。
  - **诊断增强**：`resp.Reader.tls_read_err` 保留 TLS 具体错误名；`readReply` 在 `ReadFailed` 时再带上
    `client.read_err`（`TlsBadRecordMac` / `TlsAlert` …），不再一律写成「读 socket 失败」。
  - **回归护栏**：新增单元用例「TLS 明文读取：实现写自身缓冲并返回 0 时不能当成 EOF」（mock 复刻该实现）；
    `tools/regression.ps1` 新增 `Invoke-TlsRoundTrip`（缺 python/夹具时显式 `SKIP` + 原因，不计 PASS）。
  - **验证**：单元 **44/44**（基线抬到 44）、集成 **26/26**、`RESULT=PASS`；
    TLS 阶段 `PING/SET/GET` 全 `RESULT=OK`，`GET` 取回 `LEN=5 VALUE=world`；
    撤掉修复后新用例失败（43/44），证明用例有效。
  - 夹具同步修正：`STORE` 改为**进程级共享**（跨连接可见，CLI 分次建连才能验证 SET→GET）；
    `read_exact` 读满长度（`RawIOBase.read` 会短路）。
