  - 参考实现：C# `DH.NRedis`、Rust `Pek.RRedis`；Zig 侧命名 `Pek.ZRedis`（库 `pek_zredis`）。
  - 公共基础件复用 `zzig`（`compat` 时钟/睡眠、`DateTime`），不重复造轮子。
  - 分阶段交付：本轮完成协议/连接/池/编码/基础命令/FullRedis/结构体/PubSub；
    队列、Stream、服务层、Tair、拓扑、TLS 列入下一里程碑并在 `docs/移植对照-NRedis.md` 留缺口。
  - TLS **不静默降级**：`Tls=true` / `rediss://` 当前返回 `error.Unsupported` 并写清原因。

- **2026-11-18（首轮）· 实测修正（均有证据）**
  - 句柄悬空：`Client` 按值返回后，`Reader` 保存的 `&stream`、`Client` 保存的 `*ConnConfig` 失效，
    Windows 报 `error.Unexpected NTSTATUS=0xc0000008 (INVALID_HANDLE)`；改为按值持有/快照后消除。
  - 超时：Zig 0.17 Windows Threaded 对 `netConnectIpWindows(timeout)` 是 `@panic`，
    对 `operateTimeout` 返回 `error.ConcurrencyUnavailable`；改为套接字 `SO_RCVTIMEO`/`SO_SNDTIMEO`。
  - 泄漏：`expectArray` 原转移所有权但调用方只释放数组，元素泄漏；改为借用语义后消除。
  - 验证结果：`zig build test --summary all` → **27 项通过、退出码 0**；
    集成 9 项（握手/RESP3/批量/管道/前缀搜索/锁/结构体/PubSub/池并发）。

- **2026-11-18（第七轮）· 单键命令自动选路（含各结构体）**
  - 用户原话：**「请继续，要做完全对齐迁移」**。
  - `Redis.execute` / `executeBlocking` 在启用拓扑后，按**单键命令表**（key 固定第 1 参数）自动选节点并处理
    `MOVED`/`ASK`/失败重选；结构体（哈希/列表/集合/有序集合/队列/Stream/Tair）的单键命令因而自动生效。
  - 多键（`MGET`/`DEL`/`mset`/`RENAME`/`EVAL`）与无键（`PING`/`INFO`/`CLUSTER`）仍走主池（与 C#/Rust 多键限制一致）。
  - `refreshTopology` 改为**锁外构建新拓扑再原子替换**（避免发现命令在锁内重入死锁；失败保留旧拓扑）。
  - 新增双服务端测试：`bar`(5061)→A、`foo`(12182)→B，直连两侧核对落点；结构体 `HINCRBY` 也按槽位落到对应节点。
  - 验证：单元 **43/43**、集成 **25/25**；`regression.ps1` → `RESULT=PASS`（基线 43/25）。

- **2026-11-18（第六轮）· 拓扑自动化**

- **2026-11-18（第四轮）· 完全对齐迁移：Stream / EventBus**
  - 用户原话：**「请继续，要做完全对齐迁移」**。
  - 新增 `src/queues/stream.zig`（`Message` / `StreamInfo` / `GroupInfo` / `ConsumerInfo` / `PendingInfo` / `PendingItem`）
    与 `src/services/eventbus.zig`（`RedisEventBus(T)`），`FullRedis` 补 `getStream`。
  - 实测修正（均有证据）：
    - `setGroup` 先释放旧名再 dup 新名，传入 `self.group_name` 时自别名 → 重复建组（实测 XPENDING 指向另一个组、挂起数恒 0）；改为**先复制后释放**。
    - `retryAck` 持有的组名在 `setGroup` 内被释放 → 悬空指针；改为局部 `dupe` + `defer free`。
    - `toStruct` 若用默认 `parseFromSlice` 会**借用输入缓冲**，临时缓冲释放后得到 `UUUUU` 悬空串；改为 `.allocate = .alloc_always`。
    - 手动释放 `std.json.Value` 的 arena 内容属非法（`free of invalid memory`）；改为保留 `Parsed` 并用 `deinit()` 一次性释放。
  - 验证：`zig build test` → **单元 36/36、集成 21/21**；`tools/regression.ps1` → `RESULT=PASS`（基线 36/21）。

- **2026-11-18（第二轮）· 完全对齐迁移：队列 / 服务 / Tair**
  - 用户原话：**「请继续，要做完全对齐迁移」**。
  - 新增 `src/queues/{base,status,queue,delay,reliable}.zig`、`src/services/{redlock,deferred,stat}.zig`，
    `FullRedis` 补 `getQueue/getDelayQueue/getReliableQueue/getDeferred/createSub/rename` 与 Tair `Ex*` 全家。
  - 与 Rust 参考实现逐项核对后确认的口径（均有源码证据）：
    - `EXHINCRBY` 返回**整数**（Rust `tair.rs` `as_i64()`），不是数组；`EXINCRBY` 才返回 `[值, 版本]`；
    - RedLock 加锁用**普通 SET**（Rust `services.rs` 注释与实现一致），互斥依赖「同一 key 只由一个语言端持有」的约定，
      释放用比较令牌 Lua；释放前按 `FullRedis` 前缀拼完整键（本轮修，原实现漏前缀会静默不删）；
    - 可靠队列 `rollbackAck(from, to)` 的第二参传**主队列键**（`retryAck` 内部即 `self.key`），不是消费者键。
  - 实测修正：
    - `ReliableQueue.init` 多余 `dupe` 消费者键（只用于拼 key）造成每次 `getReliableQueue` 泄漏 8 B → 改为直接格式化 `&consumer`；
    - 假 Redis 新增 `RPOPLPUSH`/`BRPOPLPUSH`、RedLock 解锁 `EVAL` 比较删除、Tair `EX*` 最小实现；
    - 推迟转移的整数推断 `i128` → 显式 `i64`。
  - 验证结果：`zig build test` → **单元 36/36、集成 17/17**；`tools/regression.ps1` → `RESULT=PASS`（基线抬到 36/17）。
