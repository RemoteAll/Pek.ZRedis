### 实测坑（勿回退）
- 按值返回结构体不能存内部指针：`Reader` 按值持有 `Stream`、`Client` 按值快照 `ConnConfig`（否则 `INVALID_HANDLE`）。
- Windows Threaded：`netConnectIpWindows` 带 timeout 是 `@panic`；`operateTimeout` 返回 `ConcurrencyUnavailable`；
  超时改套接字 `SO_RCVTIMEO`/`SO_SNDTIMEO`。
- `expectArray` 借用语义，元素由 `Value.deinit` 释放；`std.Io.Threaded.io()` 不能按值拷贝。
- `setGroup` 必须**先复制后释放**（传入自身 `group_name` 会自别名 → 重复建组、XPENDING 挂起恒 0）；`retryAck` 组名要局部 dupe。
- `std.json.parseFromSlice` 默认**借用输入**：临时缓冲必须 `.allocate = .alloc_always`（否则拿到 `UUUUU` 悬空串）。
- 不要手动释放 `std.json.Value` 内部（由 `Parsed.deinit()` 统一释放，手动 free 会 `free of invalid memory`）。
- `ReliableQueue.init` 不要额外 dupe 消费者键（曾每次 8 B 泄漏）。
- **TLS 两处致命坑**：`writer.flush()` 不冲刷 socket（要再 `stream_writer.interface.flush()`）；
  TLS `readVec` 返回 0 不代表 EOF（要用 `peekGreedy(1)`+`toss`）。

### 第十一轮（TLS 正向往返修好并纳入回归）
- **根因一（写）**：`tls_client.Client.writer.flush()` 只把密文写进 `output`（socket 写缓冲），不冲刷 socket
  （zzig `tls_client.zig` L1034-1075：`flush`/`end` 均如此，只有 `init` 末尾 `output.flush()`）。
  → `client.writeAll` 补 `stream_writer.interface.flush()`；`TlsState.destroy` 在 `end()` 后也补冲刷。
- **根因二（读）**：`std.Io.Reader` 允许实现「忽略 `data`、写自身缓冲并 `return 0`」，zzig TLS 客户端正是该形态
  （应用数据 `r.end += cleartext.len` 后 `return 0`；`NewSessionTicket` 也 `return 0`）。
  旧代码把「返回 0」当 EOF → 握手成功后立刻误判 `ConnectionClosed`。→ 改用 `peekGreedy(1)` + `toss(n)`。
- **取证手法**：带阶段日志的诊断 TLS 服务端（`accepted / handshake_ok / recv hex / recv_eof`），
  一眼看出「握手成功但零应用字节」；客户端再打印 `readVec n=0 tls_buffered=0` 定位读方向。
- 诊断增强：`resp.Reader.tls_read_err` 保留 TLS 错误名，`readReply` 在 `ReadFailed` 时附带 `client.read_err`。
- 回归护栏：单元用例「TLS 明文读取：实现写自身缓冲并返回 0 时不能当成 EOF」（mock 复刻，撤掉修复必失败）；
  `tools/regression.ps1` 新增 `Invoke-TlsRoundTrip`（缺 python/夹具显式 `SKIP`，不计 PASS）。
- 夹具：`STORE` 进程级共享（跨连接可见）；`read_exact` 读满长度。
- 基线：单元 **44** / 集成 **26**；TLS 阶段 `PING/SET/GET` 全 `RESULT=OK`，`GET` 取回 `LEN=5 VALUE=world`。

### 第十四轮（TLS 配置口径对齐 + 纠正 mTLS 误判）
